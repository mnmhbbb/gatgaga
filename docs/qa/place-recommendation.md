- 상태: **AI QA 대기 — 사용자 승인 전**
- 담당: 주 에이전트 실행·기록, QA 서브에이전트 근거 검토. 사용자는 필요한 로그인·계정 전환과 핵심 사용감 확인·최종 승인
- 기능 커밋: `5fec985` (`feat: 기존 장소에 멤버 추천 추가`)

- 기준: [PRD AC-07·Private Space 권한·일반 성공 피드백](../product/prd-v1.0.md), [화면 S-12](../design/screen-spec-v1.0.md)
- 실행 날짜·브라우저·화면 폭·검증자·실행 HEAD·미커밋 변경: 미기록
- QA 검토자·검토 결과: 미기록

## 준비

1. 사용자가 서로 다른 브라우저 프로필 또는 일반/시크릿 창에 계정 A/B를 따로 로그인하고 AI가 각 환경에 접근 가능한지 확인한다. 같은 프로필의 탭 두 개는 같은 로그인 세션을 공유하므로 계정 분리가 되지 않는다. 접근이 막힌 환경만 필요한 도움을 요청한다.
2. A가 Owner인 테스트 공간과 A가 추가한 장소를 준비한다. 직접 등록 장소와 Kakao 장소 각각 한 개로 RC-02~04를 확인한다.
3. B는 먼저 이 공간의 비멤버로 준비한다. 이전 로컬 테스트에서 멤버십을 취소한 계정을 쓰면 RC-01을 먼저 실행한 뒤 A의 유효한 초대로 참여한다. 이 DB 상태는 Git으로 복원되지 않으며 다른 환경에서는 별도 준비가 필요하다.
4. 추천 취소 UI는 없으므로 이미 B가 추천한 장소에서는 처음 추천을 재현할 수 없다. 새 테스트 장소를 사용한다.

## 기본 검증

AI가 아래 시나리오를 실행하고 실제 결과에 실행자·관찰값·필요한 증거를 기록한다. 두 계정을 번갈아 확인할 때도 브라우저 제어 담당은 한 명으로 유지한다.

| ID | 준비·실행 순서 | 기대 결과 | 실제 결과 |
| --- | --- | --- | --- |
| RC-01 | 비멤버 B에게 테스트 공간·장소 상세·장소 추가 URL 전달 → 각각 직접 접속 → A의 초대 수락 후 다시 접속 | 참여 전 404로 콘텐츠 비공개, 참여 후 접근 가능. 과거 취소 계정의 상세 404는 이전에 사용자 확인했지만 이번 실행은 별도 기록 | 미실행 |
| RC-02 | A가 추가한 장소 상세를 A/B에서 각각 확인 → B가 `추천하기` | 시작은 1명(A), A `추천했어요`, B `추천하기`. B의 성공 후 2명과 A/B 이름, B `추천했어요` 표시. 성공한 B 화면은 수동 새로고침 없이 갱신돼야 함 | 미실행 |
| RC-03 | B가 빠르게 반복 클릭 → B 화면 새로고침 → 같은 B 프로필의 두 탭에서 아직 추천하지 않은 새 장소를 열어 양쪽에서 추천 | 대기/선택 상태에서 반복 입력 방지. 새로고침 후에도 선택 유지. 동시 요청이어도 B 추천 한 개, 전체 2명 | 미실행 |
| RC-04 | A 화면을 열어 둠 → B 추천 완료 → A 탭 복귀 → 상태 기록 → A 수동 새로고침 | 자동 재조회는 현재 없음. 복귀만 했을 때의 추천 수/목록 변화를 기록하고, 새로고침 후에는 2명·A/B 표시. 새로고침 후에도 불일치하면 실패 | 미실행 |
| RC-05 | B의 추천 성공 순간 문구·toast·버튼·멤버 목록을 관찰 | PRD 일반 성공 기준은 3초 toast. 현재 추천 UI는 `추천했어요` 선택 상태만 있고 별도 toast가 없음. 이 차이는 승인 전 수정 또는 명세 조정 결정이 필요하며 선택 상태만으로 명세 충족 처리하지 않음 | 미실행 — 코드/명세 차이 있음 |
| RC-06 | 초대로 참여한 일반 멤버 B가 직접 등록 QA의 MP-01~02, MP-07을 실행 → A 새로고침 | Owner가 아닌 활성 멤버도 저장 가능. 새 장소의 최초 추천자는 B이며 A는 `추천하기`. A에서도 같은 장소·주소·출처를 확인 | 미실행 |

RC-04 결과로 실제 사용에 필요한 재조회 범위를 판단한다. 이 문서만으로 TanStack Query 도입이나 자동 갱신을 새 요구사항으로 확정하지 않는다.

- `db:test-recommend-place`는 추천 중복·제거 상태·impactVersion과 rollback의 SQL 검증이다. 실제 `recommendPlace` TypeScript·세션·화면까지 실행하는 테스트는 아니다.
- 직접 등록의 최초 추천/권한/rollback은 `db:test-manual-place`가 실제 저장 트랜잭션을 실행한다. 두 실제 계정의 화면과 세션 경계는 위 수동 검증으로 보완한다.
- 기능 커밋 시 관련 DB smoke는 통과했고 이번 문서 작업에서는 DB를 재실행하지 않았다.
