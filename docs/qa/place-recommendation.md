## 준비

1. 사용자가 서로 다른 브라우저 프로필 또는 일반/시크릿 창에 계정 A/B를 따로 로그인하고 AI가 각 환경에 접근 가능한지 확인한다. 같은 프로필의 탭 두 개는 같은 로그인 세션을 공유하므로 계정 분리가 되지 않는다. 접근이 막힌 환경만 필요한 도움을 요청한다.
2. A가 Owner인 테스트 공간과 A가 추가한 장소를 준비한다. 직접 등록 장소와 Kakao 장소 각각 한 개로 RC-02~04를 확인한다.
3. B는 먼저 이 공간의 비멤버로 준비한다. 이전 로컬 테스트에서 멤버십을 취소한 계정을 쓰면 RC-01을 먼저 실행한 뒤 A의 유효한 초대로 참여한다. 이 DB 상태는 Git으로 복원되지 않으며 다른 환경에서는 별도 준비가 필요하다.
4. 추천 취소 UI는 없으므로 이미 B가 추천한 장소에서는 처음 추천을 재현할 수 없다. 새 테스트 장소를 사용한다.

## 사용자에게 전달할 요약

- AI QA 결과: 기본 6개와 권한 취소·로그아웃 후 요청 거부 통과. 추천 성공 피드백 수정·재검증. 통신 장애 미실행. 열린 다른 탭은 새로고침 전까지 이전 추천 수 표시
- 필요한 사용자 판단: 추천 사용감 확인, 목록·상세의 탭 복귀 재조회 필요 여부, 통신 장애 미실행 항목 처리와 최종 승인. A/B 로그인·B MEMBER 복구 완료, QA 임시 B 두 번째 탭은 닫음
- AI QA 후 사용감 확인: 추천하지 않은 장소에서 `추천하기`를 한 번 사용하고 완료 상태와 추천한 멤버를 쉽게 이해할 수 있는지 확인한다. 두 계정·중복·권한 케이스 전체를 다시 실행할 필요는 없다.
