- 함께 확인할 문서: [멤버 추천과 접근 권한](place-recommendation.md)

## 준비

1. 로컬 PostgreSQL과 앱을 실행한다. 저장소에서 `nvm use 24.18.1`, `pnpm db:up`, `pnpm dev`를 사용하고 터미널에 표시된 앱 주소로 접속한다. 기존 `.env`의 Kakao/인증 설정을 사용한다.
2. 계정 A로 Kakao 로그인하고 A가 활성 멤버인 테스트 공간을 연다. 테스트 데이터가 실제 저장되며 제거 UI는 아직 없으므로 이름에 `QA-날짜-순번`을 붙인다.
3. 검색 0건용 고유 문자열(예: `QA-직접등록-20261003-01-없는장소`)과 실제로 아는 주소, 근처 장소명을 준비한다. Kakao 결과는 변할 수 있으므로 0건이 아니면 다른 고유 문자열을 사용한다.
4. 기본 검증은 일반 브라우저에서 수행하고 MP-11은 폭 360px에서도 반복한다. 지원 검증의 Offline/차단 설정은 각 케이스 후 해제한다.

## 지원 검증

재현이 안 되면 통과로 적지 않고 원인과 관찰값을 남긴다. 일반 UI로 준비할 수 없는 DB 상태를 만들기 위해 사용자가 임의로 SQL을 실행할 필요는 없다.

| ID | 준비·실행 순서 | 기대 결과·판정 주의 | 실제 결과 |
| --- | --- | --- | --- |
| MP-S01 | 직접 등록 폼 진입 후 DevTools Network를 Offline으로 전환 → 새로운 주소 검색 → Online 복구 → 재검색 | 장애 안내를 표시하고 검색 0건으로 오인시키지 않음. 이름 유지, 복구 후 검색 가능. 캐시 등으로 실제 실패하지 않았다면 미실행 | 미실행 |
| MP-S02 | 위치 선택 완료 → Offline → 저장 → 오류 확인 → Online → 같은 폼에서 재시도 | 오류 후 이름·위치 유지. 복구 후 저장 완료 및 장소·추천 각 하나. 이 케이스는 서버 저장 후 응답만 유실된 상황을 보장하지 않음 | 미실행 |
| MP-S03 | 같은 브라우저의 다른 탭에서 로그아웃 → 남아 있는 직접 등록 폼에서 저장 | 서버가 세션을 다시 확인해 저장을 거부하고 로그인 진입 화면으로 이동. 재로그인 후 목록에 해당 시도가 추가되지 않음 | 미실행 |
| MP-S04 | AI와 로컬 전용 환경에서 지도 SDK 초기화 실패를 재현 → 재시도. 별도로 타일 요청 실패 시 표시 관찰 | 초기화 실패 시 오류·`지도 다시 불러오기`, 저장 비활성, 복구 후 지도 표시. **현재 코드는 Map/Marker 생성 직후 준비 완료로 처리하므로 타일 표시 완료를 보장하지 않음**. 빈 지도인데 저장 가능하면 현상을 기록하고 승인 전 처리 판단 | 미실행 — 실패 주입 준비 필요 |
| MP-S05 | AI 지원으로 저장은 성공했으나 응답만 유실된 상황을 재현 → 폼을 닫지 않고 재시도 | 같은 상세로 연결되고 장소/최초 추천 각 하나, `이미 이 공간에 있는 장소예요` 안내. 최초 저장 내용 유지. 재현 없이 MP-S02 통과만으로 이 케이스를 통과 처리하지 않음 | 미실행 — 응답 유실 재현 필요 |

권한은 [추천·권한 QA의 RC-01/RC-S01](place-recommendation.md)과 함께 확인한다. 비멤버·취소 멤버·비활성 User, 다른 공간/등록자/출처 ID 재사용, 제거된 연결, 추천 생성 실패 rollback은 실제 트랜잭션 DB 테스트로 확인했다. 제거·복구 UI는 미구현이므로 UI 검증 통과라고 기록하지 않는다.
