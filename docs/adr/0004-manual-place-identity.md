# ADR-0004: 직접 등록 장소의 식별자와 재시도

- 상태: **Accepted — 구현 완료**
- 결정일: 2026-10-01
- 관련 문서: [`../development/technical-design-v1.0.md`](../development/technical-design-v1.0.md), [`../development/erd-v0.1.md`](../development/erd-v0.1.md)

## 배경

직접 등록 장소는 Provider ID가 없고 이름·좌표로 자동 병합하지 않는다. 저장 응답이 유실된 뒤 같은 폼에서 재시도해도 Place·SpacePlace·최초 추천이 중복 생성되지 않아야 한다.

## 결정

- 직접 등록 폼의 첫 저장 시 UUID v4를 만들고 해당 폼의 재시도에 같은 값을 보낸다. 서버는 이 값을 새 `Place.id`로 사용한다.
- 서버 세션과 활성 User·Membership을 확인한 뒤 `USER` 출처·세션 사용자를 등록자로 강제한다. 클라이언트의 출처·등록자·Kakao ID·외부 URL은 저장하지 않는다.
- 기존 Place ID와 충돌하면 같은 등록자·같은 Space의 직접 등록 장소만 기존 상세로 반환한다. 다른 사용자·공간·Kakao 장소의 ID는 정보나 연결을 제공하지 않는다.
- 같은 ID의 제거된 연결은 복구 필요로 응답한다. 중복 요청으로 장소 사실을 덮어쓰지 않는다.
- Place·SpacePlace·최초 추천을 한 트랜잭션으로 저장한다. 기존 PK·unique·출처 CHECK를 사용하고 schema·migration은 변경하지 않는다.

## 대안

- 요청마다 서버에서 새 UUID 생성: 응답 유실 뒤 재시도에 중복이 생긴다.
- 이름·주소·좌표 unique 또는 근사 병합: 같은 위치의 서로 다른 장소를 구분하지 못하고 제품 정책과 충돌한다.
- 별도 idempotency 테이블: 현재 폼의 재시도에는 기존 Place PK로 충분하다.

## 결과와 재검토 조건

새로 연 폼은 별도 등록이다. 새로고침·화면 이탈을 넘어 미완료 등록을 복원하거나 여러 기기에서 같은 초안을 이어가는 요구가 생기면 초안 저장·별도 요청 키를 검토한다. 위치 검색의 Kakao 결과는 위치 후보로만 사용하며 저장된 직접 등록 장소의 출처를 바꾸지 않는다.
