# ADR-0003: 초대 링크 재복사와 저장 방식

- 상태: **Accepted — 구현 전**
- 결정일: 2026-09-19
- 관련 문서: [`../product/prd-v1.0.md`](../product/prd-v1.0.md), [`../design/screen-spec-v1.0.md`](../design/screen-spec-v1.0.md), [`../development/erd-v0.1.md`](../development/erd-v0.1.md)

## 배경

Private Space에는 활성 초대 링크가 하나다. 기존 설계는 토큰 해시만 DB에 저장하므로 발급 후 같은 링크를 다시 보여줄 수 없다. 복사할 때마다 재발급하면 이미 친구에게 보낸 링크까지 무효가 되어, 여러 시점에 사람을 초대하는 흐름과 맞지 않는다.

## 결정

- 링크는 자동 만료하지 않는다. Owner가 명시적으로 폐기하거나 재발급할 때까지 유효하다.
- Owner는 같은 활성 링크를 언제든 다시 복사할 수 있다. 복사는 토큰을 교체하지 않는다.
- 재발급은 기존 링크가 즉시 무효가 된다는 확인을 받은 뒤 실행한다. Space당 활성 초대 하나를 유지한다.
- 초대 토큰의 SHA-256 해시는 참여 요청의 조회에 사용한다. 재복사를 위해 토큰을 인증된 방식으로 암호화해 DB에 추가로 저장하고, 복호화는 서버에서 Owner 권한 확인 후에만 수행한다.
- 암호화 키는 DB와 분리된 서버 비밀값으로 관리한다. 평문 토큰을 DB·로그·분석 이벤트·OAuth callback URL에 남기지 않는다.
- 현재 Prisma schema와 migration에는 해시만 있다. 암호문 필드와 키 설정은 초대 기능 구현 시 추가하고 실제 PostgreSQL에서 검증한다.

## 대안과 이유

| 대안 | 선택하지 않은 이유 |
| --- | --- |
| 해시만 저장하고 최초 발급 시 한 번만 복사 | 나중에 다시 공유하려면 재발급해야 하며 기존에 보낸 링크가 깨짐 |
| 평문 토큰 저장 | DB 읽기 권한이 유출되면 자동 만료하지 않는 모든 활성 링크가 바로 노출됨 |
| 매번 새 링크 발급 | Space당 활성 링크 하나와 오래 유지되는 공유 링크라는 제품 정책에 맞지 않음 |

## 결과와 재검토 조건

서버에 암호화 키와 복호화 경로가 추가된다. 키를 잃으면 기존 링크의 재복사는 불가능하지만 해시로 검증하는 기존 링크 자체는 계속 작동하므로 Owner가 새 링크를 발급할 수 있다. 키 유출이 의심되면 활성 링크를 폐기·재발급한다. 반복적인 유출이나 악용이 확인되면 자동 만료·사용 범위를 다시 검토한다.

암호화 방식은 직접 설계하지 않고 서버 런타임의 검증된 인증 암호화 기능을 사용한다. [OWASP Cryptographic Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)의 인증된 암호화·키 분리 원칙을 따른다.
