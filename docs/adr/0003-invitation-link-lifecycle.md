# ADR-0003: 초대 링크 재복사와 토큰 재생성

- 상태: **Accepted — 구현 완료**
- 결정일: 2026-09-20
- 관련 문서: [`../product/prd-v1.0.md`](../product/prd-v1.0.md), [`../design/screen-spec-v1.0.md`](../design/screen-spec-v1.0.md), [`../development/erd-v0.1.md`](../development/erd-v0.1.md)

## 배경

Private Space에는 활성 초대 링크가 하나다. DB에는 조회용 토큰 해시만 저장하지만 Owner는 같은 링크를 나중에도 다시 복사할 수 있어야 한다. 복사할 때마다 재발급하면 이미 친구에게 보낸 링크까지 무효가 되어 제품 흐름과 맞지 않는다.

## 결정

- 링크는 자동 만료하지 않는다. Owner가 명시적으로 폐기하거나 재발급할 때까지 유효하다.
- Owner는 같은 활성 링크를 언제든 다시 복사할 수 있다. 복사는 토큰을 교체하지 않는다.
- 재발급은 기존 링크가 즉시 무효가 된다는 확인을 받은 뒤 실행한다. Space당 활성 초대 하나를 유지한다.
- 초대 토큰은 서버 master key에서 파생한 전용 키와 invitation ID·space ID를 HMAC-SHA-256에 넣어 만든다. 같은 초대 행에는 같은 32바이트 토큰이 재생성된다.
- DB에는 기존 `tokenHash`만 저장한다. 참여 요청은 SHA-256 해시로 조회하고, Owner 재복사는 토큰을 재생성한 뒤 저장 해시와 timing-safe 비교가 성공할 때만 링크를 반환한다.
- master key는 DB와 분리한다. 평문 토큰과 별도 암호문을 DB·로그·분석 이벤트·OAuth callback URL에 남기지 않는다.
- 링크 토큰 키와 로그인 복귀 intent 서명 키는 HKDF-SHA-256으로 용도별 분리한다.

구현은 Node.js 표준 `crypto`만 사용한다. 로그인 복귀 intent는 invitation ID와 10분 만료 시각만 담아 HMAC 서명한다.

초대 URL은 `/invite#token`으로 만들고 fragment를 받은 브라우저가 주소에서 즉시 제거한 뒤 Server Action에서 intent cookie로 교환한다. 따라서 장기 토큰은 OAuth callback URL과 일반 요청 URL에 전달되지 않는다.

## 대안과 이유

| 대안 | 선택하지 않은 이유 |
| --- | --- |
| 해시만 저장하고 최초 발급 시 한 번만 복사 | 나중에 다시 공유하려면 재발급해야 하며 기존에 보낸 링크가 깨짐 |
| AES-256-GCM 암호문 추가 저장 | 기존 링크를 유지한 키 교체에는 유리하지만 P0에는 새 DB 컬럼·migration·복호화 경로가 더 큰 비용이다 |
| 평문 토큰 추가 저장 | DB 읽기 권한이 유출되면 자동 만료하지 않는 모든 활성 링크가 바로 노출됨 |
| 매번 새 링크 발급 | Space당 활성 링크 하나와 오래 유지되는 공유 링크라는 제품 정책에 맞지 않음 |

## 결과와 재검토 조건

P0에서는 `SPACE_INVITATION_MASTER_KEY`를 안정적으로 유지한다. 키를 잃거나 바꾸면 기존 링크의 재복사는 불가능하지만 해시로 검증하는 링크 자체는 계속 작동하므로 Owner가 새 링크를 발급할 수 있다. 키 유출이 의심되면 활성 링크를 모두 폐기·재발급한다.

기존 링크를 끊지 않는 정기 키 교체가 실제 요구가 되면 암호문 저장이나 key version을 다시 검토한다. 반복적인 유출이나 악용이 확인되면 자동 만료·사용 범위도 함께 검토한다.
