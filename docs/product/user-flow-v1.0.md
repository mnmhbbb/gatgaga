- 최종 업데이트: 2026-09-06
- 상태: **v1.0 확정 — 개발 기준선**
- 범위: Private Alpha P0
- 시각화: [같가가 P0 사용자 플로우 FigJam](https://www.figma.com/board/dilV1C9TVEYGCfRO4bUPhh)
- 기준 문서: [`prd-v1.0.md`](./prd-v1.0.md)

## 1. 이 문서의 역할

PRD의 기능을 사용자가 실제로 밟는 순서로 정리한다. 디자인은 이 흐름에 필요한 화면과 상태를 빠짐없이 제공하고, 기술 설계는 이 흐름을 안전하게 실행하는 데이터·API·권한 구조를 만든다.

Private Alpha의 핵심 루프는 다음 한 줄이다.

> 공간을 만들거나 참여한다 → 장소를 함께 모은다 → 목록과 지도에서 다시 찾는다 → 추천과 글·댓글을 남긴다

## 2. P0 사용자 흐름

### A. 첫 공간 만들기

```text
서비스 진입 → 로그인 → 내 공간 → 공간 만들기
→ 이름 입력 → Private 공간 생성 → 빈 공간 홈
```

- 공간 이름만 필수로 입력한다.
- Private이 P0 고정값이며 선택 UI는 만들지 않는다.
- 생성 직후 가장 강한 행동은 `첫 장소 추가`다.

### B. 초대로 참여하기

```text
초대 링크 진입 → 로그인 여부 확인
→ 필요하면 로그인 → 초대 확인 → 참여 → 공간 홈
```

- 로그인 전 접근해도 로그인 후 원래 초대 흐름으로 돌아온다.
- 이미 참여한 사용자의 반복 수락은 같은 Membership으로 끝난다.
- 초대 링크는 자동 만료하지 않으며 Owner가 폐기·재발급한다.

### C. 장소 검색으로 추가하기

```text
공간 홈 → 장소 추가 → Kakao 키워드 검색
→ 결과 선택 → 지도·주소 확인 → 이 장소 추가 → 장소 상세
```

- 저장과 글 작성을 분리해 장소 저장만으로 끝낼 수 있다.
- 같은 공간에 이미 있는 Kakao 장소면 새로 만들지 않고 기존 상세로 보낸다.

### D. 검색 결과가 없을 때 직접 등록하기

```text
검색 결과 없음 → 직접 등록 → 장소명 확인
→ 주소나 근처 장소 검색 → 위치 후보 선택
→ 지도 핀 확인 → 직접 등록 → 장소 상세
```

- 원래 검색어를 장소명에 미리 채운다.
- 현재 위치 권한은 요청하지 않는다.
- 사용자가 선택한 위치의 주소와 좌표를 저장한다.
- 직접 등록 장소는 Kakao 장소와 자동 병합하지 않는다.

### E. 장소를 다시 찾기

```text
공간 홈 → 목록 또는 지도 → 장소 선택 → 장소 상세
```

- 기본 보기는 목록이다.
- 지도는 별도 데이터가 아니라 같은 장소 집합의 전환 보기다.
- 장소가 없을 때는 빈 지도를 열지 않고 `첫 장소 추가`를 보여준다.

### F. 같은 장소에 기여하기

```text
장소 상세 → 추천하기
장소 상세 → 글쓰기 → 장소 글 상세 → 댓글
```

- 추천과 글 작성은 독립 행동이다.
- 장소 글과 댓글은 작성자만 수정·삭제한다.
- 공동 편집이나 버전 충돌 UI는 사용하지 않는다.

### G. 잘못 추가한 장소 제거하기

```text
장소 상세 → 이 공간에서 제거 → 영향 확인
→ soft delete → 5초 동안 실행 취소
```

- 최초 등록자는 다른 멤버의 활성 추천·글·댓글이 없을 때만 제거할 수 있다. 최초 등록자의 자동 추천은 타인 기여가 아니다.
- Owner는 연결된 추천·글·댓글 영향 범위를 확인한 뒤 제거할 수 있다.
- 5초 실행 취소는 제거자 본인만 가능하고, 이후 복구는 Owner만 가능하다.
- 지도 Provider의 장소가 아니라 현재 공간의 연결만 제거한다.
- 제거된 Kakao 장소나 기존 내부 Place ID는 복구로 연결하되 직접 등록 장소의 이름·좌표를 근사 비교해 자동 병합하지 않는다.

## 3. 출시 단계별 기능 순서

| 순서 | 기능 묶음 | 단계 | 이 순서인 이유 |
| --- | --- | --- | --- |
| 1 | 로그인·내 공간 | P0 | 사용자와 접근 권한의 기준점 |
| 2 | Private 공간 생성·초대 | P0 | 여러 사람이 같은 맥락에 들어오는 기반 |
| 3 | Kakao 검색·장소 저장·중복 방지 | P0 | 제품의 가장 짧은 핵심 가치 |
| 4 | 직접 등록 | P0 | 검색 실패가 핵심 루프를 막지 않게 함 |
| 5 | 목록·지도·장소 상세 | P0 | 저장한 후보를 비교하고 다시 찾게 함 |
| 6 | 추천·장소 글·평면 댓글 | P0 | 공동 수집을 공동 판단과 대화로 연결 |
| 7 | 작성자 수정·삭제·장소 제거 | P0 | 실제 사용에서 생기는 실수를 안전하게 처리 |
| 8 | Public 공간·비로그인 열람 | P1 | Private 핵심 루프 검증 후 유입 확장 |
| 9 | 사진·대댓글·일반 게시글 | P1 | 대화 밀도를 확인한 뒤 콘텐츠 확장 |
| 10 | Unlisted·투표·랭킹·알림·현재 위치 | P2 | 반복 수요와 지표가 생긴 뒤 재평가 |

## 4. 기술 단계로 넘어가는 조건

아래 조건을 기준으로 제품·UX 기획 단계를 종료하고 기술 설계와 제품 저장소 초기화로 넘어간다.

1. FigJam의 P0 흐름에 빠진 진입·분기·종료가 없다.
2. Figma에 P0 대표 화면과 빈 상태·로딩·오류·권한 없음 상태가 표현되어 있다.
3. `공간 만들기`, `장소 추가`, `직접 등록`, `추천`, `글·댓글`, `제거`의 주 행동 문구가 확정됐다.
4. 제작자가 프로토타입에서 핵심 과업을 끝까지 수행해 흐름을 확인했다.
5. 실제 데이터가 연결된 Alpha 공개 전 사용자 한 명에게 같은 과업을 검증한다.
6. P1·P2 기능이 P0 구현에 섞이지 않았다.

이 게이트를 통과한 뒤 인증, 데이터 모델, API, 권한, 동시성, 배포 순서로 기술 설계를 확정한다.
