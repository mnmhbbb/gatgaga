# 같가가 PRD v1.0

- 제품명: 같가가(가칭)
- 이름 의미: `같이 가요, 가요`에서 출발한 줄임말
- 내부 도메인 용어: `Space`
- 사용자 노출 용어: `공간`(가칭)
- 최종 업데이트: 2026-09-06
- 상태: **v1.0 확정 — 개발 기준선**
- 문서 역할: 제품 범위·정책·수용 기준의 단일 기준(SSOT)

> 이 문서는 Private Alpha에서 실제로 만들 범위를 확정한다. 장기 제품 방향은 보존하되, P0가 아닌 기능은 첫 구현을 지연시키지 않는다.

## 1. 제품 정의

> 여러 사람이 하나의 공간에 장소를 함께 모으고, 장소마다 추천과 이야기를 이어가는 서비스

같가가는 여행 계획, 동네 맛집, 언젠가 가고 싶은 곳, 방문 후 기록 등 특정 사용법을 강제하지 않는다. 다만 첫 검증은 `2~5명의 지인이 방문 후보 장소를 함께 수집하는 상황`에 집중한다.

### 해결하려는 문제

- 여러 사람이 발견한 장소와 관련 대화가 서로 다른 채널에 흩어진다.
- 기존 개인 저장 목록은 다른 멤버가 장소와 정보를 함께 보태기 어렵다.
- 시간이 지나면 누가 왜 추천했는지 다시 찾기 어렵다.

### 핵심 가치 가설

> 장소를 빠르게 함께 저장하고, 그 장소를 추천한 사람과 각자의 글·댓글을 한곳에서 다시 확인할 수 있다.

### 제품 원칙

1. 기능 수보다 사용성을 우선한다.
2. 설명 없이 찾고, 적게 입력하고, 즉시 완료할 수 있어야 한다.
3. 장소 저장과 글 작성을 분리해 저장을 가볍게 끝낸다.
4. 사용 목적은 열어두되 첫 화면과 테스트 과업은 구체적으로 만든다.
5. 모바일 브라우저와 PWA를 첫 클라이언트로 삼는다.

## 2. 사용자와 첫 검증 상황

### 장기 사용자 범위

친구, 연인, 가족, 동료 또는 공개 커뮤니티와 장소를 모으고 싶은 누구나 사용할 수 있다.

### Private Alpha 사용자

- 제작자를 포함한 지인 약 5명
- 한 Space당 2~5명
- 함께 식사·카페·모임 장소를 정할 일이 있는 관계
- 최소 두 명 이상이 같은 Space에 기여할 수 있는 그룹

### 핵심 JTBD

> 다른 사람과 장소 후보를 정할 때, 장소와 의견을 하나의 지속적인 공간에 함께 모아 나중에도 쉽게 비교하고 다시 보고 싶다.

## 3. 출시 단계와 우선순위

| 우선순위 | 의미 | 원칙 |
| --- | --- | --- |
| P0 | Private Alpha 필수 | 이것 없이는 핵심 루프를 검증할 수 없음 |
| P1 | Alpha 이후 우선 | 사용 증거 또는 Public 확장에 필요 |
| P2 | 탐색 후보 | 요청과 지표를 확인한 뒤 재평가 |

### P0 — Private Alpha

#### 인증·공간·초대

- Better Auth와 Kakao OAuth 1개
- 비밀번호·이메일 로그인 없이 `카카오로 계속하기`만 제공
- 최소 프로필: 표시 이름, 프로필 이미지
- 참여 중인 Private Space 목록
- 이름만 입력하는 Private Space 생성
- Owner·Member 두 역할
- Space당 활성 초대 링크 1개
- 초대 링크는 자동 만료하지 않으며 Owner가 폐기·재발급한다.
- 로그인 후 원래 초대 흐름으로 복귀한다.
- Private 콘텐츠는 활성 멤버만 읽고 쓸 수 있다.

#### 장소 검색·저장·지도

- Kakao Maps 키워드 검색
- 검색 결과에 장소명, 카테고리, 주소를 표시한다.
- 사용자는 `지역 + 장소명`으로 검색 범위를 좁힐 수 있다.
- 검색 결과가 없으면 장소명과 지도 위치를 확인해 직접 등록한다.
- Kakao 장소와 직접 등록 장소의 출처를 구분한다.
- 게시글 없이 장소만 빠르게 저장할 수 있다.
- 같은 Space의 동일 장소는 하나만 존재한다.
- 이미 저장된 장소를 다시 선택하면 기존 장소 상세로 연결한다.
- Space 홈 기본 보기는 목록이며 지도는 같은 장소 집합의 전환 보기다.
- 지도 핀과 목록 선택 상태를 연결한다.

#### 추천·장소 글·댓글

- 장소를 처음 추가한 멤버의 추천을 함께 생성한다.
- 추천하지 않은 멤버는 `추천하기`로 추천을 남기고, 선택 상태는 `추천했어요`로 표시한다.
- 멤버 1명당 장소별 활성 추천은 하나다.
- 추천과 장소 글 작성은 서로 독립적이다.
- 활성 멤버는 장소마다 제목 없는 텍스트 글을 여러 개 작성할 수 있다.
- 장소 글은 최대 1,000자다.
- 장소 글에 평면 텍스트 댓글을 작성할 수 있다.
- 글과 댓글은 각각 작성자만 수정·삭제한다.
- Owner도 다른 멤버의 원문을 수정하지 않는다.

#### 장소 제거·복구

- 최초 등록자는 다른 멤버의 기여가 생기기 전까지만 장소를 제거할 수 있다.
- 최초 등록자의 자동 추천은 다른 멤버의 기여로 보지 않는다.
- 다른 멤버의 활성 추천·글·댓글이 하나라도 있으면 다른 멤버의 기여가 생긴 것으로 본다. soft delete된 글·댓글은 영향 수에서 제외한다.
- Owner는 영향 범위를 확인한 뒤 장소를 제거할 수 있다.
- 제거는 전역 지도 장소 삭제가 아니라 현재 Space의 `SpacePlace` soft delete다.
- 연결된 추천·글·댓글은 함께 비노출하며 데이터는 보존한다.
- 제거 직후 5초 동안 제거자 본인에게 `실행 취소`를 제공한다.
- 이후 복구는 Owner만 할 수 있다.
- 제거된 동일 Kakao 장소 또는 기존 내부 Place ID로 재진입하면 새 객체 대신 복구 흐름으로 안내한다. 직접 등록 장소의 이름·좌표 근사 병합은 하지 않는다.

#### 클라이언트 품질

- 360px 이상 모바일 웹을 우선 지원한다.
- PWA 설치에 필요한 manifest, 아이콘과 HTTPS 배포 기준을 마련한다.
- 최소 터치 영역은 44px다.
- safe area, 가상 키보드, 브라우저 뒤로가기를 정상 처리한다.
- 로딩·빈 상태·성공·오류·권한 없음 상태를 정의한다.
- 실패 시 검색어와 작성 초안을 가능한 한 보존한다.

### P1 — Alpha 이후

- Public Space 생성과 비로그인 열람
- Public Space 검색과 로그인 후 즉시 가입
- Public Space의 비로그인·비멤버 사용자는 열람만 가능하고, 장소 추가·추천·글·댓글은 로그인 후 가입한 멤버만 가능하다.
- 공간 생성·설정에서 `Private | Public`을 선택할 수 있게 하되 기본값은 `Private`다.
- Ban, 신고, 콘텐츠 숨김과 최소 운영 기능
- 게시글 사진 최대 3장과 S3 업로드
- 한 단계 대댓글과 부모 작성자 태그
- 일반 Space 게시글과 활동 피드
- 선택적 방문 상태·방문 기록
- 자발적 탈퇴, 소유권 이전과 Space 삭제

### P2 — 사용자 근거가 생긴 뒤 재검토

- `Unlisted` 공개 범위
- 투표
- 인기·추천 랭킹과 개인화
- 알림
- 여러 장소가 첨부된 게시글
- React Native 앱 또는 WebView 전용 브리지
- 현재 위치 기반 검색과 지도 영역 재검색

### 현재 위치 검색 결정

Private Alpha에는 현재 위치 검색을 넣지 않는다.

- Kakao 검색 결과의 주소와 `지역 + 장소명` 검색으로 초기 탐색 목적을 충족한다.
- 위치 권한 요청, 거부, 시간 초과, 낮은 정확도와 기기별 테스트 상태를 추가하면 첫 핵심 루프가 복잡해진다.
- 위치 추적이나 좌표 저장은 하지 않는다.
- 사용자 테스트에서 `내 주변` 요구가 반복되거나 검색 실패가 관찰될 때만 P2를 재평가한다.

## 5. 핵심 사용자 흐름

### 흐름 A — 공간 생성과 초대

```text
로그인 → 내 공간 → Private 공간 생성 → 초대 링크 복사
→ 친구가 링크 진입 → 로그인 → 초대 수락 → 같은 공간 진입
```

### 흐름 B — 장소 추가

```text
공간 홈 → 장소 추가 → Kakao 키워드 검색 → 결과 선택
→ 지도·주소 확인 → 이 장소 추가 → 장소 상세
```

검색 결과가 없으면 `직접 등록 → 장소명·주소/지역 검색 → 지도 위치 확인 → 추가`로 분기한다.

### 흐름 C — 같은 장소에 기여

```text
장소 상세 → 추천하기 또는 글쓰기 → 장소 글 상세 → 댓글
```

### 흐름 D — 잘못 추가한 장소 제거

```text
장소 상세 → 이 공간에서 장소 제거 → 영향 확인 → soft delete
→ 제거자 본인은 5초 내 실행 취소 또는 이후 Owner 복구
```

## 6. 상호작용 피드백 기준

| 유형 | 동작 |
| --- | --- |
| 일반 성공 | 하단 토스트, 3초 후 자동 종료 |
| 제거처럼 되돌릴 수 있는 성공 | 하단 토스트와 `실행 취소`, 5초 후 종료 |
| 사용자 조치가 필요한 오류 | 원인과 재시도/닫기 제공, 자동 종료하지 않음 |
| 필드 오류 | 해당 입력 가까이에 표시하고 입력값 유지 |
| 저장 중 | 중복 제출을 막고 진행 상태 표시 |

- 토스트는 한 번에 하나만 보여준다.
- 토스트는 `role="status"` 또는 적절한 live region으로 보조기기에 알린다.
- 성공 문구는 완료 대상을 구체적으로 쓴다. 예: `연남서식당을 이 공간에 추가했어요.`

## 8. 성공 기준과 검증

### 제품 행동 지표

- 서로 다른 두 명이 같은 Space에 기여한다.
- 장소 추가 후 다른 멤버가 추천·글·댓글 중 하나를 남긴다.
- 첫 핵심 행동 후 7일 안에 한 명 이상이 같은 Space를 다시 연다.

### 사용성 기준

- 지인 5명 중 4명 이상이 도움 없이 장소 검색·추가를 완료한다.
- 지인 5명 중 4명 이상이 목록과 지도를 전환하고 장소 상세를 연다.
- 지인 5명 중 4명 이상이 `추천`과 `장소 글`의 차이를 설명한다.
- 지인 5명 중 4명 이상이 자신의 글만 수정할 수 있음을 이해한다.
- 장소 제거가 지도 서비스의 장소 자체를 삭제한다고 오해하는 사용자가 없어야 한다.

표본이 작으므로 수치만으로 성공·실패를 단정하지 않고 관찰 메모와 인터뷰를 함께 본다.

## 9. 비기능 요구사항

### 보안·개인정보

- Private 리소스는 추측 가능한 ID만으로 접근할 수 없다.
- 초대 토큰 원문은 DB에 저장하지 않고 해시를 저장한다.
- 객체 단위 권한 검사로 다른 Space의 데이터 접근을 막는다.
- Kakao JavaScript 키는 공개 가능한 식별자이지만 허용 도메인을 제한하고 별도 비밀키는 브라우저에 노출하지 않는다.

### 성능·신뢰성

- 검색·목록·지도는 모바일 네트워크를 기준으로 불필요한 요청과 렌더링을 줄인다.
- 핵심 쓰기는 DB 제약, 트랜잭션과 멱등 처리로 중복 요청에 안전해야 한다.
- 지도 로드 실패 시 목록으로 돌아갈 수 있어야 한다.
- 인증·DB·Kakao Provider 오류를 구분해 기록한다.

### 비용

- Vercel, Neon, Kakao Maps와 이후 S3 사용량에 예산 알림과 상한을 둔다.
- 외부 API 무료 쿼터와 정책은 배포 전에 다시 확인한다.

## 10. 확정 결정과 열린 결정

### 확정

- 첫 출시: Private Alpha
- 기본 공개 범위: Private
- Public은 삭제된 범위가 아니라 P1이며, 비로그인 열람과 로그인 후 가입·작성을 지원한다.
- 지도 Provider: Kakao Maps
- 인증: 앱에서 운영하는 Better Auth + Kakao OAuth
- 현재 위치 검색: 제외, 사용자 근거가 있을 때 재검토
- 기본 화면: 장소 목록, 지도는 전환 보기
- 콘텐츠: 장소 글과 평면 댓글
- 수정 권한: 작성자만
- 삭제: soft delete
- 클라이언트: 모바일 우선 PWA
- 저장소: `gatgaga`는 실제 제품, `gatgaga-prototype`은 읽기 전용 사용성 참고 자료

### 기술 설계에서 확정

- 인증·제품 데이터의 ERD와 PostgreSQL 제약
- 글·댓글 soft delete 보존 기간과 물리 삭제 시점
- 분석·오류 추적 도구
- Vercel·Neon 리전과 배포 환경 구분

### P1 착수 전에 결정

- Public ↔ Private 변경 정책
- Public 멤버 정보 노출 범위
- 신고·Ban·운영 정책
- 이미지 형식·용량·변환·정리 정책
