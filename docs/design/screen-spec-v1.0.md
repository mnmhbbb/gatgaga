# 같가가 화면 명세 v1.0

- 최종 업데이트: 2026-09-06
- 상태: **v1.0 확정 — 개발 기준선**
- 기준 제품 문서: `../product/prd-v1.0.md`
- 참고 구현: 현재 Next.js UI 프로토타입
- Figma: https://www.figma.com/design/9GZnf5yYi1ypClTuib1C4m/
- 대상: 360px 이상 모바일 웹·PWA, 데스크톱 반응형
- 문서 역할: 화면·상태·상호작용의 단일 기준(SSOT)

## 1. 목적

이 문서는 PRD의 정책을 사용자가 실제로 보고 누르는 화면으로 번역한다. Figma에서는 이 문서의 모든 화면을 똑같은 수의 페이지로 만들기보다, 핵심 흐름과 중요한 상태를 프레임으로 표현한다.

Figma는 시각 참고 자료이고 이 문서가 화면 동작의 기준이다. Starter 호출 한도로 Figma와 문서가 일시적으로 다르면 이 문서의 Eucalyptus Sage 토큰, 문구, 상태와 권한 규칙을 우선한다.

### 최우선 UX 목표

> 처음 보는 사용자도 설명 없이 장소를 검색해 추가하고, 목록·지도에서 다시 찾고, 장소에 글을 남길 수 있어야 한다.

### 설계 원칙

1. 화면마다 가장 중요한 행동은 하나만 강하게 보인다.
2. 장소 추가는 글 작성 없이 끝낼 수 있다.
3. 목록과 지도는 같은 장소 집합을 보는 두 방식이다.
4. 추천, 장소 글, 댓글은 문구와 위치로 역할을 구분한다.
5. 수정·삭제 권한은 Jira 같은 충돌 UI가 아니라 익숙한 게시판 방식으로 표현한다.
6. 실패해도 사용자의 입력과 이동 맥락을 최대한 보존한다.
7. 현재 위치 권한을 요청하지 않는다.

## 3. 전역 레이아웃과 내비게이션

### 모바일 기준

- 최소 viewport: 360px
- 콘텐츠 최대 너비: 430px
- 최소 터치 영역: 44×44px
- 본문 기본 크기: 16px 이상을 우선해 모바일 브라우저 확대를 방지한다.
- 하단 고정 CTA와 toast는 `safe-area-inset-bottom`을 반영한다.
- 가상 키보드가 열린 상태에서 입력과 등록 버튼이 가려지지 않아야 한다.

### 내비게이션

- 전역 시작점은 `내 공간`이다.
- Space 내부는 스택 방식으로 이동한다.
- 상시 하단 탭은 두지 않는다.
- Space 홈 안에서만 `목록 | 지도` 전환을 사용한다.
- 뒤로가기는 코드의 `arrow-left` SVG를 사용하는 44×44px `IconButton`으로 만들고 제목과 별도 요소로 배치한다.
- 텍스트 문자 `<`나 제목에 포함된 화살표 문자를 뒤로가기 아이콘으로 사용하지 않는다.
- 브라우저 뒤로가기는 화면의 뒤로가기와 같은 결과를 만든다.
- 검색 결과에서 장소 확인 후 돌아가면 검색어와 결과를 유지한다.
- 글 작성 중 본문이 있으면 이탈 확인을 제공한다.

### 현재 프로토타입 경로

| 경로 | 목적 |
| --- | --- |
| `/` | 데이터가 있는 Private Space 시나리오 |
| `/start` | `내 공간 → 공간 만들기 → 첫 장소 추가` 신규 사용자 시나리오 |

실제 제품 URL은 기술 설계에서 리소스 기반 라우트로 바꾼다.

## 5. 핵심 화면 상세

### S-04~05 내 공간·공간 만들기

- `내 공간`의 `공간 만들기`를 누르면 별도 생성 화면으로 이동한다.
- P0 입력값은 공간 이름 하나다. 빈 값은 생성할 수 없다.
- 공개 범위는 `Private`로 고정하고 `초대 링크를 받은 사람만 참여할 수 있어요`라고 설명한다.
- P0에는 비활성 `Public` 옵션이나 준비 중 UI를 노출하지 않는다. P1 착수 시 `Private | Public` 선택 카드와 각각의 열람·작성 권한 설명을 설계한다.
- 생성 성공 시 새 공간의 빈 목록 화면으로 이동하고 3초 성공 toast를 표시한다.
- 생성 직후에는 `장소 추가`를 주 행동, `친구 초대`를 보조 행동으로 제공한다.

### S-06 공간 홈·목록

정보 순서:

1. 브랜드 표시와 Space 이름
2. `목록 | 지도` 전환
3. 정렬 설명과 장소 수
4. 장소 카드 목록
5. 하단 또는 엄지 영역의 `장소 추가`

장소 카드에는 다음만 표시한다.

- 장소명
- 카테고리와 주소
- 최신 장소 글 일부 또는 빈 상태
- 댓글 수
- 추천한 멤버와 추천 수

상태:

- 로딩: 카드 skeleton
- 빈 상태: `첫 장소를 함께 모아볼까요?` + `첫 장소 추가`
- 정상: 최근 추천된 순으로 목록
- 오류: 목록을 유지할 수 있으면 비차단 안내, 불가능하면 재시도

### S-07 공간 홈·지도

- 목록과 동일한 `SpacePlace` 집합을 Marker로 표시한다.
- 장소가 0개라면 임의의 지역으로 지도 SDK를 열지 않는다. `아직 지도에 표시할 장소가 없어요`와 `첫 장소 추가` CTA가 있는 빈 상태를 표시한다.
- 첫 장소가 생기면 해당 장소를 중심으로 지도를 처음 연다.
- 핀 선택 전에는 `핀을 눌러 장소를 확인하세요`를 짧게 안내한다.
- 핀 선택 후 모바일 하단에 장소 카드가 나타난다.
- 카드 선택 시 장소 상세로 이동한다.
- 지도 로딩 실패 시 오류 설명과 `목록으로 보기`를 제공한다.
- 현재 위치 버튼과 지도 영역 재검색은 표시하지 않는다.

### S-08 장소 검색

- 검색창은 첫 진입 시 focus한다.
- 권장 placeholder: `장소명 또는 지역 + 장소명을 검색하세요`
- Enter와 `검색` 버튼은 같은 동작을 한다.
- 빈 검색어는 요청하지 않는다.
- 결과에는 장소명, 카테고리와 전체 주소를 표시한다.
- 결과의 주소가 검색 범위를 판단하는 기준이며 현재 위치는 사용하지 않는다.
- 새 검색어 입력 시 이전 오류는 지우되, 사용자가 검색하기 전까지 이전 결과를 급히 비우지 않는다.

상태:

| 상태 | 표시 |
| --- | --- |
| 초기 | 간단한 검색 안내와 예시 |
| 로딩 | 결과 영역 skeleton, 중복 제출 방지 |
| 성공 | 결과 수와 결과 목록 |
| 0건 | 검색 결과 없음 + `직접 등록하기` |
| 오류 | 입력값 유지 + 원인에 맞는 안내 + `다시 검색` |

### S-10 장소 확인

- 상단에 선택 장소의 실제 지도와 Marker를 표시한다.
- 장소명, 출처, 카테고리와 주소를 확인한다.
- Kakao 장소면 `카카오맵에서 보기`를 제공한다.
- 기본 CTA는 `이 장소 추가`다.
- 이미 Space에 있으면 추가하지 않고 `이미 이 공간에 있는 장소예요`와 `기존 장소 보기`를 제공한다.

### S-11 직접 등록

- 검색어를 장소명으로 미리 채운다.
- 사용자는 주소 또는 지역을 검색해 위치 후보를 선택한다.
- 선택 주소의 지도와 Marker를 확인한다.
- 장소명과 위치가 모두 있어야 추가할 수 있다.
- `직접 등록한 장소` 출처를 명확히 표시한다.
- Kakao 장소와 자동 병합하지 않는다.

현재 위치를 직접 등록의 기본값으로 사용하지 않는다. 주소 검색과 지도 확인으로 위치를 정한다.

### S-12 장소 상세

정보 순서:

1. 지도와 Provider 장소 정보
2. 장소명·카테고리·주소·출처
3. 추천한 멤버
4. 보조 CTA `추천하기`
5. 주 CTA `글쓰기`
6. 최신순 장소 글 목록

- 추천하지 않아도 글을 쓸 수 있다.
- 추천 버튼 기본 문구는 `추천하기`, 선택 상태는 `추천했어요`로 통일한다.
- `나도 추천`처럼 기존 추천자 존재 여부에 따라 달라지는 문구는 사용하지 않는다.
- `추천했어요` 상태는 반복 요청을 만들지 않는다.
- 더보기에는 권한이 있을 때만 `이 공간에서 장소 제거`를 표시한다.

### S-13 장소 글 작성

- 제목 없이 본문만 입력한다.
- 최대 1,000자, 빈 값 등록 불가
- `취소`와 `등록`을 명확히 분리한다.
- 등록 중 버튼을 비활성화하고 중복 제출을 막는다.
- 실패하면 화면과 초안을 유지한다.
- 성공하면 장소 상세로 돌아가고 3초 성공 toast를 표시한다.

### S-14~15 장소 글 상세·관리

- 작성자, 작성 시각, 수정 여부와 본문을 표시한다.
- 자신의 글에만 `수정`, `삭제`를 표시한다.
- 다른 사람 글에는 수정·삭제 메뉴가 없다.
- 별도 공동 편집, 버전 충돌, `다른 수정이 있었어요` UI를 사용하지 않는다.
- 글 삭제 시 확인하고 soft delete한다.
- 댓글이 남아 있으면 `삭제된 글입니다` 상태로 구조를 유지한다.
- 댓글은 평면 목록이며 자신의 댓글에만 수정·삭제 메뉴를 제공한다.

### S-16 장소 제거 확인

- 제목: `이 공간에서 제거할까요?`
- 지도 서비스의 장소 자체는 삭제되지 않음을 설명한다.
- 함께 숨겨질 추천·장소 글·댓글 수를 표시한다.
- `취소`와 위험 CTA `이 공간에서 제거`를 제공한다.
- 실행 시 서버가 최신 권한과 영향 수를 다시 확인한다.
- 성공하면 제거자 본인의 목록으로 이동하고 5초 동안 `장소를 제거했어요. 실행 취소` toast를 표시한다.

## 6. 피드백·오류·토스트 규칙

### Toast

| 종류 | 시간 | 행동 |
| --- | --- | --- |
| 추가·수정·댓글 성공 | 3초 | 자동 종료, 닫기 가능 |
| 장소 제거 성공 | 5초 | `실행 취소`, 자동 종료, 닫기 가능 |
| 오류 | 자동 종료 없음 | 재시도 또는 닫기 |

- 한 번에 하나만 표시하고 새 메시지가 이전 메시지를 대체한다.
- 모바일 하단 고정 CTA가 있으면 그 위에 표시한다.
- 키보드가 열렸을 때 입력을 가리지 않는다.
- `role="status"`와 `aria-live="polite"`를 기본으로 사용한다.
- 제거자 본인이 5초 안에 `실행 취소`를 누르면 toast를 닫고 복구 성공을 화면에서 즉시 반영한다. 이후 복구는 Owner용 복구 화면에서 처리한다.

### 오류 문구

- 문제와 다음 행동을 함께 쓴다.
- 내부 코드와 Provider 원문 오류를 노출하지 않는다.
- 예: `장소를 검색하지 못했어요. 네트워크를 확인하고 다시 시도해주세요.`

### 확인이 필요한 행동

- 장소 제거, 글 삭제처럼 다른 맥락에 영향을 주는 행동만 확인한다.
- 단순 저장·추천·댓글에는 확인 모달을 사용하지 않는다.

## 7. 핵심 클릭 프로토타입 흐름

### 성공 흐름

```text
빈 Space → 첫 장소 추가 → 검색 → 장소 확인 → 추가
→ 장소 글 작성 → 댓글 → 목록 → 지도 → 핀 → 장소 상세
```

### 예외 흐름

```text
장소 검색 → 이미 저장된 장소 → 기존 장소 상세 → 추천하기

장소 상세 → 제거 확인 → 제거 toast → 실행 취소

장소 검색 → 결과 없음 → 직접 등록 → 위치 확인 → 추가
```

## 8. Figma 완료 조건

- Foundations 값이 코드 토큰과 연결되어 있다.
- 모든 P0 화면의 대표 상태가 한 번 이상 표현되어 있다.
- 검색 로딩·0건·오류·중복 상태가 빠지지 않는다.
- 목록과 지도 전환 후 선택 장소의 흐름이 연결된다.
- 자신의 글과 다른 사람 글의 권한 차이를 확인할 수 있다.
- 장소 제거와 실행 취소를 눌러볼 수 있다.
- 360px 기준에서 텍스트 잘림과 CTA 겹침이 없다.
- 현재 위치 권한을 요청하는 화면이나 버튼이 없다.

## 9. 디자인 이후 검증

지인 1명에게 15~20분 동안 다음 과업만 설명 없이 수행하게 한다.

1. 장소를 검색하고 추가한다.
2. 목록에서 지도로 바꾸고 핀을 통해 상세로 들어간다.
3. 추천하지 않은 장소에 글과 댓글을 남긴다.
4. 자신의 글만 수정할 수 있음을 확인한다.
5. 장소를 제거하고 실행 취소한다.

과업 실패, 3초 이상 멈춘 지점, 사용자가 한 말과 기대한 결과를 기록한다. 같은 문제를 2명 이상 겪거나 핵심 과업을 완료하지 못하면 디자인을 수정한다.
